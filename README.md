# MediBook

منصة عربية متجاوبة لإدارة وحجز مواعيد المندوبين الطبيين مع العيادات، مبنية باستخدام Next.js وTypeScript وTailwind CSS وSupabase.

## الحالة الحالية

هذه نسخة تأسيسية قابلة للتطوير وليست نظاماً إنتاجياً مكتمل الاعتماد بعد. تشمل:
- صفحة تعريفية عربية RTL.
- إنشاء حساب وتسجيل دخول عبر Supabase Auth.
- لوحة أولية تقرأ الحجوزات وفق صلاحيات قاعدة البيانات.
- SQL للجداول والعلاقات وسياسات RLS.
- إجراء خادمي لقبول أو رفض الطلب وإرسال إشعار داخل قاعدة البيانات.
- تحديثات Realtime مبدئية للحجوزات.

لا تزال هناك أجزاء تحتاج استكمالاً قبل الإطلاق التجاري: إنشاء واجهة كاملة لإدارة الفترات الزمنية والعيادات والشركات، إعادة الجدولة، تأكيد الحضور، إدارة المستخدمين، تدقيق الأمان واختبارات الحمل والتزامن.

## المتطلبات

- Node.js 20 أو أحدث (يوصى بإصدار LTS).
- npm.
- حساب Supabase.
- حساب Vercel للنشر (اختياري محلياً).

## 1. التشغيل محلياً

```bash
npm install
cp .env.example .env.local
npm run dev
```

افتح http://localhost:3000

أضف عنوان مشروع Supabase ومفتاح العميل العام (publishable/anon) إلى `.env.local`. لا تستخدم مفتاح `service_role` في المتصفح أو في متغير يبدأ بـ `NEXT_PUBLIC_`.

## 2. إعداد Supabase من الصفر

1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor.
3. انسخ محتوى `supabase/schema.sql` وشغّله في مشروع جديد فارغ.
4. من إعدادات API انسخ Project URL ومفتاح publishable/anon إلى `.env.local`.
5. من Authentication > URL Configuration اضبط Site URL على عنوان التطوير المحلي أثناء التطوير، ثم حدّثه إلى نطاق الإنتاج بعد النشر.
6. أنشئ أول مستخدم من صفحة التسجيل.
7. الحسابات الجديدة تُسجل افتراضياً بدور `rep` عمداً. لا يُسمح للمستخدم بتعيين نفسه مديراً أو طبيباً من بيانات التسجيل.
8. يلزم أن يربط المدير الحسابات بالشركات والعيادات من خلال واجهة إدارية موثوقة أو SQL آمن. لا تفتح صلاحيات الإدارة للعامة.

### تهيئة مدير النظام

بعد إنشاء حسابك من صفحة التسجيل، استخرج معرّف المستخدم من Authentication > Users. في SQL Editor نفّذ الأمر التالي بعد استبدال UUID بمعرّف حسابك:

```sql
update public.profiles
set role = 'admin'
where id = 'PUT-YOUR-AUTH-USER-UUID-HERE';
```

نفّذ هذا يدوياً على مشروعك فقط، ولا تعرض واجهة عامة تسمح بتغيير الدور إلى `admin`.

## 3. كيف تُنشئ بيانات الاختبار؟

بعد تعيين حساب مدير، أنشئ شركة وعيادة وأعضاء ارتباطاً بحسابات موثوقة. يجب أن تكون جميع UUIDs صحيحة من `auth.users` / `profiles`.

مثال إرشادي لإنشاء عيادة:
```sql
insert into public.clinics (name, address)
values ('عيادة تجريبية', 'الموصل');
```

لإضافة طبيب أو سكرتير إلى العيادة، استخدم `clinic_members` مع معرّف المستخدم والدور المناسب. لإضافة مندوب لشركة، استخدم `company_reps`. أنشئ فترات مستقبلية في `availability_slots` من حساب مخوّل.

## 4. فحص المشروع

```bash
npm run dev
npm run build
```

لا تعتبر المشروع جاهزاً للإنتاج قبل حل أي أخطاء build، وإكمال الاختبارات الواردة أدناه.

## 5. النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub خاص.
2. سجّل الدخول إلى Vercel واختر Add New Project ثم استورد المستودع.
3. أضف متغيرات البيئة:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. انشر المشروع.
5. أضف نطاق Vercel في Supabase Authentication > URL Configuration، وحدد Site URL وعناوين إعادة التوجيه المسموحة.
6. اختبر التسجيل، تأكيد البريد، تسجيل الدخول، قراءة البيانات، وعمليات القرار بعد النشر.

## الأمان قبل الإنتاج

- فعّل RLS على كل جدول يحتوي بيانات خاصة.
- لا تضع مفاتيح سرية في GitHub أو في المتصفح.
- راجع سياسات RLS مع حساب مندوب وحساب عيادة وحساب غير مصرح.
- اختبر محاولات تغيير `rep_id` أو `clinic_id` أو `company_id` في الطلب.
- اختبر حجزين متزامنين للفترة نفسها؛ منطق منع التعارض الحالي في إجراء القرار يحتاج تقوية إضافية إذا كان هناك أكثر من عملية قبول متزامنة. استخدم قفلاً مناسباً على مستوى العيادة أو قيوداً/جدولة ذرية في قاعدة البيانات.
- أضف سجلاً تدقيقياً للقرارات وتغييرات المواعيد.
- أضف Rate limiting للحسابات وواجهات API.
- اضبط سياسات كلمات المرور وتأكيد البريد والاسترداد.
- لا تخزن بيانات المرضى أو معلومات صحية حساسة؛ المنصة مخصصة لتنسيق الزيارات المهنية.
- تحقق من المتطلبات القانونية والتنظيمية المحلية قبل التشغيل التجاري.

## مسار التطوير التالي

1. واجهة إدارة الشركات والعيادات والمستخدمين.
2. واجهة إنشاء طلب حجز مرتبطة بالفترات المتاحة.
3. إدارة الفترات الأسبوعية وسعة كل فترة.
4. إعادة الجدولة مع موافقة الطرفين.
5. قائمة اليوم وتسجيل الحضور.
6. مركز إشعارات وPush notifications.
7. اختبارات آلية وصلاحيات شاملة.
